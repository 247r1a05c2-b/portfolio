# Public portfolio readiness checklist

Use this checklist before sending the portfolio to scholarship committees, professors, or employers.

## Accuracy

- [ ] Confirm every internship's company, dates, role, work performed, and completion status. Describe virtual or training-based placements exactly as issued by the provider; do not claim production work unless it happened.
- [ ] Keep the CGPA, education dates, certifications, and competition claims consistent with official records.
- [ ] For every project, distinguish implemented features from planned work and demo behavior.
- [ ] Do not claim accuracy, speed, users, or evaluation results unless a reproducible measurement supports the number.
- [ ] Add screenshots, setup steps, tests, and a short architecture diagram for the two strongest projects.

## Privacy and security

- [ ] Review the public `resume1.docx` file and confirm you intentionally want the full document to be publicly downloadable. Remove personal address, signatures, ID numbers, or other details not needed for applications.
- [ ] Search repository history and deployment settings for API keys, passwords, tokens, and database credentials.
- [ ] Do not publish raw face datasets, real student attendance records, or private medical images.
- [ ] Verify that public demo deployments do not expose admin actions or secrets.

## Research readiness

- [ ] Publish a reproducible evaluation protocol for TraceGaurd and NexaRAG, including baselines, datasets, metrics, and limitations.
- [ ] Report results only after running the experiments and retaining the raw outputs.
- [ ] Keep a clean commit history and ensure the CI build passes before applications.
